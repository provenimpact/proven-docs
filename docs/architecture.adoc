== Overview

Proven Docs is a Node.js CLI tool for working with AsciiDoc documentation. Its primary function is converting AsciiDoc files to publishable PDF artifacts via a rendering pipeline: AsciiDoc source is converted to HTML, enriched with syntax highlighting and Mermaid diagram support, then printed to PDF using a headless Chromium-based browser detected on the host system.

The CLI provides four subcommands: `render` (AsciiDoc to PDF conversion), `watch` (file monitoring with automatic re-render), `validate` (structural and syntax checking without rendering), and `info` (document metadata inspection). Each subcommand is an independent module under `src/commands/`.

The tool is designed to work fully offline, integrate into CI pipelines, and produce deterministic output. It ships as both an npm package (for Node.js users) and standalone platform-specific binaries (for users without Node.js), built via `bun build --compile`.

== Container View (C4 Level 2)

Proven Docs is a single CLI process with a modular command structure. The CLI dispatches to subcommands, each of which composes the shared pipeline modules as needed. A browser discovery module detects a system-installed Chromium-based browser (Chrome, Edge, or Chromium) at runtime, used by the `render` and `watch` commands for PDF printing.

== Data Flow

=== Render pipeline (render and watch commands)

....
.adoc file (disk)
  -> fs.readFileSync() -> AsciiDoc source (string)
    -> @asciidoctor/core convert() -> HTML document (string, with inline fonts)
      -> enrich.js: highlight.js server-side -> highlighted code blocks
      -> enrich.js: transform mermaid blocks -> <pre class="mermaid">
        -> browser.js: discoverBrowser() -> executablePath
          -> playwright-core page.setContent() -> browser DOM
          -> page.addScriptTag(mermaid.min.js) -> mermaid loaded
            -> page.evaluate(mermaid.render) -> SVG diagrams
              -> page.pdf() -> PDF bytes
                -> disk write -> .pdf file (disk)
....

=== Validate flow (validate command)

....
.adoc file (disk)
  -> fs.readFileSync() -> AsciiDoc source (string)
    -> @asciidoctor/core load() with MemoryLogger -> parsed document + messages
      -> Walk AST: find mermaid blocks -> mermaid.parse() per block -> errors
      -> Walk AST: find code blocks -> hljs.getLanguage() per block -> warnings
    -> Report errors and warnings to stderr
....

=== Info flow (info command)

....
.adoc file (disk)
  -> fs.readFileSync() -> AsciiDoc source (string)
    -> @asciidoctor/core load() -> document object
      -> doc.getDocumentTitle() -> title
      -> doc.getAttributes() -> all attributes
      -> Filter internals, format output -> stdout
....

All data flows within a single process. No network calls, no persistence beyond the output file. Syntax highlighting happens server-side in Node.js. Mermaid rendering happens browser-side in Chromium (requires DOM). The validate and info commands operate entirely in Node.js without a browser.

== Cross-Cutting Concerns

=== Error Handling

All errors are caught at the command layer and reported to stderr with descriptive messages. The CLI exits with code 0 on success and code 1 on any failure. Error categories:

* File not found / not readable (input validation)
* AsciiDoc rendering errors (asciidoctor.js)
* Browser launch failure (Playwright/Chromium) -- render and watch only
* PDF write failure (file system) -- render and watch only
* Mermaid syntax errors (validate command)

The watch command catches render errors and continues watching rather than exiting.

=== Output Verbosity

All subcommands support `--verbose` and `--quiet` flags (mutually exclusive, enforced by a shared validator). Verbose mode adds diagnostic messages to stderr. Quiet mode suppresses non-error stdout output.

=== Offline Operation

The tool requires no network access during operation. Browser discovery is a local file-system check that finds a system-installed Chromium-based browser (Chrome, Edge, or Chromium). AsciiDoc rendering and validation are entirely in-process. Mermaid syntax checking uses the npm package's parse API in Node.js. This satisfies the project Connectivity constraint.
