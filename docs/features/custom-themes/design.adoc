== Technical Context

Proven Docs is a Node.js ESM CLI tool that converts AsciiDoc files to PDF via a multi-stage pipeline: AsciiDoc → HTML → enrich → PDF. The render pipeline currently uses Asciidoctor's default stylesheet with bundled Google Fonts (replaced by inline `@font-face` declarations referencing local woff2 files). There is no support for custom styling, HTML templates, or document metadata exposure.

This feature extends the pipeline with a theming layer that sits between HTML enrichment and PDF printing. It adds CSS theme override, HTML template wrapping with attribute substitution, document metadata exposure as data attributes, and a built-in classified template.

Existing modules affected: `src/render.js`, `src/commands/render.js`, `src/commands/watch.js`, `src/print.js`.

== Decisions and Constraints

* <<../../adrs/0001-asciidoctor-js-for-rendering.adoc#,ADR-0001>>: Use @asciidoctor/core for AsciiDoc rendering
* <<../../adrs/0002-playwright-for-pdf.adoc#,ADR-0002>>: Use Playwright with Chromium for headless PDF printing
* <<../../adrs/0003-commander-for-cli.adoc#,ADR-0003>>: Use Commander.js for CLI framework

**Template engine decision (unrecorded — no ADR):** Use a minimal custom Mustache-style substitution function rather than importing a template library. Rationale: the substitution logic is trivial (replace `{{attr}}` with escaped values, `{{{attr}}}` with unescaped values), adding a dependency for this introduces licensing and maintenance burden with no benefit. The implementation is ~20 lines of code.

Project constraints:

* **Licensing**: No copyleft-licensed dependencies. No new dependencies are introduced by this feature — the template engine is custom code.
* **Connectivity**: Must work fully offline. Theme and template files are local paths only.

== Research and Unknowns

All unknowns have been resolved:

* **CSS `@page` support in Chromium**: Chromium's print-to-PDF engine supports CSS `@page` rules including margin boxes (`@top-center`, `@bottom-left`, etc.) via `printBackground: true`. This enables per-page headers and footers in custom themes. However, margin box support has limitations — `content: attr()` from the document body does not work in margin boxes. Headers/footers must use `position: fixed` elements instead for reliable attribute-driven content.
* **Asciidoctor document attributes API**: `@asciidoctor/core`'s `convert()` returns an HTML string. To access document attributes, we need to use `load()` first (which returns a Document object with `getAttributes()`), then `convert()` on the document. The `load()` + `convert()` approach replaces the current single-call `convert()`.
* **Font path resolution**: When a CSS theme references fonts via relative paths in `@font-face` declarations, the paths must be resolved relative to the CSS file's directory. Since we inject CSS into an HTML data URI (no file: URL base), we must rewrite relative font paths in the CSS to absolute `file://` URLs or data URIs before injection.
* **Built-in template resolution**: Built-in templates (like `classified`) are shipped in an `assets/templates/` directory. When `--template classified` is provided (no path separator, no file extension), the system resolves it as a built-in template name rather than a file path.

=== AsciiDoc Renderer Changes (`src/render.js`)

The renderer currently calls `asciidoctor.convert(source, options)` directly, which returns HTML but discards document attributes. The function signature changes to return both the HTML and the attributes map.

Current signature:
....
renderToHtml(source: string, baseDir?: string): string
....

New signature:
....
renderToHtml(source: string, baseDir?: string): { html: string, attributes: Record<string, string> }
....

Implementation change:

1. Call `asciidoctor.load(source, options)` to get a Document object
2. Extract attributes via `document.getAttributes()` — returns an object of all document attributes
3. Call `document.convert()` to get the HTML body
4. For standalone mode, reconstruct the full HTML document using `document.convert()` with standalone option, or use `asciidoctor.convert()` as before
5. Return `{ html, attributes }`

Since `load()` then `convert()` on the document produces the same output as `asciidoctor.convert()`, this is a non-breaking change in behavior — only the return type changes. All callers (`src/commands/render.js`, `src/commands/watch.js`) must be updated to destructure the return value.

=== Theme Engine (`src/theme.js`) — New Module

Responsibility: Apply CSS theme overrides, resolve templates, substitute attributes, and inject metadata into the HTML.

Exports:

* `applyTheme(html: string, attributes: Record<string, string>, options: ThemeOptions): string`

Where `ThemeOptions` is:
....
{
  themePath?: string,     // Absolute path to custom CSS file
  templatePath?: string,  // Absolute path or built-in name for HTML template
}
....

==== Step 1: Inject data attributes on root element

Add `data-*` attributes to the `<body>` tag for every document attribute. This makes attributes accessible to CSS selectors and `@page` rules.

Transform: `<body ...>` → `<body data-classification="CONFIDENTIAL" data-handling="INTERNAL ONLY" ...>`

Attribute names are sanitised: lowercase, hyphens preserved, underscores converted to hyphens. Only user-defined and well-known attributes are included (skip internal Asciidoctor attributes like `outfilesuffix`, `doctype`, etc. — filter by excluding attributes that start with common Asciidoctor internal prefixes).

==== Step 2: CSS theme application

When a custom CSS path is provided:

1. Read the CSS file from disk
2. Resolve relative font paths (`url(...)` references) to absolute `file://` paths relative to the CSS file's directory
3. Replace the Asciidoctor default `<style>` block in `<head>` with the custom CSS
4. Preserve the highlight.js CSS (injected by the enricher) — it comes after the main stylesheet

When no custom CSS is provided, the default stylesheet remains unchanged.

==== Step 3: Template application

When a template path is provided:

1. Resolve the template: if the path contains no separator and no extension (e.g., `classified`), look in `assets/templates/<name>/template.html`. Otherwise treat as a file path.
2. Read the template HTML from disk
3. Substitute `{{attribute-name}}` placeholders with HTML-escaped attribute values
4. Substitute `{{{attribute-name}}}` placeholders with raw (unescaped) attribute values
5. Substitute `{{{body}}}` with the rendered AsciiDoc HTML body (extracted from the `<body>` tag of the enriched HTML)
6. If a referenced attribute is not set, substitute an empty string

When a built-in template is selected and has a companion CSS theme (e.g., `assets/templates/classified/theme.css`), the companion theme is applied automatically unless `--theme` is also provided (explicit theme overrides the companion).

When no template is provided, the HTML passes through unchanged (with data attributes injected).

==== Font path resolution

When processing CSS `@font-face` declarations:

1. Parse `url(...)` values in the CSS
2. If the URL is relative (not `data:`, not `http:`, not `file:`), resolve it relative to the CSS file's directory
3. Read the font file and convert to a base64 data URI: `data:font/woff2;base64,...`
4. Replace the original URL with the data URI

This ensures fonts are embedded in the HTML regardless of how the browser loads the page.

=== Built-in Classified Template

The classified template ships at `assets/templates/classified/`:

**`template.html`**: A complete HTML document with:

* A classification banner in the header (colour-coded by `:classification:` value)
* A cover page section with metadata fields (title, author, classification, handling, distribution, document-id, review-date, department)
* The document body injected via `{{{body}}}`
* A footer with document-id and classification

**`theme.css`**: Styles for:

* Classification banner colours: PUBLIC (green), INTERNAL (amber), CONFIDENTIAL (red), RESTRICTED (dark red/purple)
* Cover page layout
* Header and footer positioning using `position: fixed` elements
* CSS `@page` rules for A4 margins accommodating header/footer
* Print-optimised typography

When `:classification:` is not set in the document, the template uses conditional CSS (`[data-classification=""] .classification-banner, body:not([data-classification]) .classification-banner { display: none }`) to hide the banner elements.

=== Command Changes

==== Render Command (`src/commands/render.js`)

New options:

* `--theme <path>` — path to a custom CSS file
* `--template <path>` — path to a custom HTML template or built-in name

Modified pipeline:

1. Read and validate input file (existing)
2. Render AsciiDoc to HTML + extract attributes (modified — destructure new return type)
3. Enrich HTML (existing)
4. **Apply theme** (new — call `applyTheme()` if `--theme` or `--template` is provided)
5. Print to PDF (existing)

Error handling for new options:

* Theme file not found: `Error: Theme file not found: <path>` + exit 1
* Template file not found: `Error: Template file not found: <path>` + exit 1
* Theme file not readable: `Error: Cannot read theme file: <path>` + exit 1

Validation of `--theme` and `--template` happens before the render pipeline starts (fail fast).

==== Watch Command (`src/commands/watch.js`)

Same new options as render. The theme and template are loaded on each re-render (not cached), so changes to theme/template files take effect on the next file change. The watch command does not watch theme/template files for changes — only `.adoc` files.

== Story Resolution

=== US-001: Apply a Custom CSS Theme

Components:: Theme Engine (`src/theme.js`), Render Command, Watch Command
Criteria::
* When the user provides `--theme`, apply custom CSS instead of default → Theme Engine reads CSS, resolves font paths, replaces default stylesheet in HTML `<head>` (THM-001)
* CSS file format accepted → Theme Engine reads `.css` files from disk (THM-002)
* Watch mode applies custom theme on every re-render → Watch command passes theme options through on each render cycle (THM-003)
* Default stylesheet when no `--theme` → Theme Engine is not invoked for CSS replacement; default Asciidoctor styles remain (THM-004)
* Error on missing theme file → Render/watch command validates file exists before pipeline starts (THM-005)
* Error on unreadable theme file → Render/watch command validates file is readable before pipeline starts (THM-006)

=== US-002: Use a Custom HTML Template

Components:: Theme Engine (`src/theme.js`), Render Command
Criteria::
* Template injection via `--template` → Theme Engine reads template, extracts body from enriched HTML, injects body into `{{{body}}}` placeholder (THM-007)
* Mustache-style attribute substitution → Theme Engine replaces `{{attr}}` with HTML-escaped values from document attributes (THM-008)
* Triple-brace body injection → Theme Engine replaces `{{{body}}}` with raw HTML body, and `{{{attr}}}` with unescaped attribute values (THM-009)
* Combined template and theme → Both paths execute sequentially: CSS replacement then template application (THM-010)
* Error on missing template → Render command validates template file/name exists before pipeline starts (THM-011)
* Default HTML wrapper when no `--template` → Theme Engine skips template application; enriched HTML passes through with only data attribute injection (THM-012)

=== US-003: Surface Document Metadata in Templates

Components:: AsciiDoc Renderer (`src/render.js`), Theme Engine (`src/theme.js`)
Criteria::
* All document attributes as template variables → Renderer extracts attributes via `document.getAttributes()`; Theme Engine uses them for substitution (THM-013)
* Document attributes as `data-*` on root element → Theme Engine injects `data-*` attributes on the `<body>` tag (THM-014)
* Empty string for unset attributes → Theme Engine substitution replaces unmatched placeholders with empty string (THM-015)

=== US-004: Built-in Classified Document Template

Components:: Theme Engine (`src/theme.js`), Built-in template assets (`assets/templates/classified/`)
Criteria::
* Built-in classified template via `--template classified` → Theme Engine resolves `classified` as a built-in name to `assets/templates/classified/template.html` (THM-016)
* Colour-coded classification banner → Classified template CSS applies colour based on `data-classification` attribute value (THM-017)
* Cover page with metadata fields → Classified template HTML includes a cover page section with `{{attribute}}` placeholders for all metadata fields (THM-018)
* Omit banner when classification not set → Classified template CSS hides banner when `data-classification` is empty or absent (THM-019)
* Support multiple classification levels → Classified template CSS defines distinct styles for PUBLIC, INTERNAL, CONFIDENTIAL, RESTRICTED (THM-020)

=== US-005: Custom Fonts in Themes

Components:: Theme Engine (`src/theme.js`)
Criteria::
* Font paths relative to theme directory → Theme Engine resolves relative `url()` references in CSS `@font-face` rules to data URIs using the CSS file's directory as base (THM-021)
* woff2 font support → Theme Engine reads woff2 files and encodes as `data:font/woff2;base64,...` (THM-022)
* Warning on missing font → Theme Engine logs a warning to stderr for missing font files and continues rendering with fallback fonts (THM-023)

=== US-006: Test Fixtures for Theme Verification

Components:: Test fixtures (`tests/fixtures/`), test suites
Criteria::
* Fixture files for content types → Fixture directory contains `.adoc` files for plain text, mermaid, code, includes, and metadata (THM-024)
* Reusable across tests → Fixture paths are imported/referenced by multiple test files across features (THM-025)
* Metadata attributes accessible in rendered output → Tests using `with-metadata.adoc` assert that attributes appear as `data-*` on the root element and in template substitutions (THM-026)
